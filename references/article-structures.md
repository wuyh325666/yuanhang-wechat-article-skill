# Article Structures

## Story Entry

Use when the pain is familiar and easy to dramatize.

Shape:

1. concrete scene
2. reader frustration
3. sharp diagnosis
4. method introduction
5. execution steps
6. closing reminder

Best for: AI tools, productivity workflows, repeated work pain.

## Sharp Opinion

Use when the article needs stronger IP feel or a more clickable opening.

Shape:

1. blunt claim
2. why most people get it wrong
3. corrected mental model
4. practical framework
5. proof/checklist
6. final punchline

Best for: second brain myths, tool misuse, productivity misconceptions.

## Practical Checklist

Use when the title promises "how to", "tutorial", "setup", or "one-week plan".

Shape:

1. define outcome
2. prerequisites
3. step-by-step setup
4. sample prompts/templates
5. inspection criteria
6. seven-day or first-run plan

Best for: Obsidian setup, Codex tutorials, AI workflow implementation.

## Framework Explainer

Use when the topic needs conceptual clarity and execution.

Shape:

1. pain in a few paragraphs
2. misconception correction
3. framework overview
4. component-by-component explanation
5. concrete example
6. implementation plan

Best for: LLM Wiki, Agent workflows, knowledge systems.

## Comparison Draft Labels

When producing multiple versions, label them clearly:

- V1 执行框架版: balanced and safest final draft
- V2 场景故事版: strongest reader identification
- V3 观点犀利版: strongest IP attitude and title impact
- V4 实操清单版: easiest to save and follow
